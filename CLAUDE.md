## Architecture

Single-screen interactive "Talking Tom" toy. All UI logic lives in one client component.

- **`app/page.js`** — the entire app. A `"use client"` component driven by an `appState` string state machine:
  `idle` → `mouthOpen` → `upload` → `singing` → `stopped` → (`exitExperience`) → `idle`.
  Each state renders a full-bleed background PNG from `public/images/` plus its own button(s). The uploaded audio/video is held as a hidden `<audio>`/`<video>` element via `mediaRef`; a user-supplied file becomes an object URL (`URL.createObjectURL`) that is revoked on exit. The "singing" mouth animation is a `setInterval` cycling `currentFrame` over 16 preloaded frames (`public/images/singing/frame-01..16.png`) at 100ms.
- **`app/layout.js`** — minimal root layout; sets `metadata` and imports `globals.css`.
- **`app/globals.css`** — Tailwind v4 (`@import "tailwindcss"`, config via `@theme inline`). Note it still references `--font-geist-sans`/`--font-geist-mono` from the create-next-app template even though `layout.js` no longer wires up `next/font`; component styling is otherwise plain class names like `.app`, `.background`, `.screen-button`, `.mouth-button`, `.upload-modal` (these class rules are not currently defined anywhere — layout is effectively unstyled).

### JS vs TS

The repo was scaffolded as TypeScript (`tsconfig.json`, `next-env.d.ts`, `.ts` config files remain) but the `app/` files were converted to plain `.js` — `app/layout.tsx` / `app/page.tsx` are deleted in git and replaced by `.js` equivalents. `allowJs` is on. Add new app code as `.js`/`.jsx` to match, unless deliberately reintroducing TS.

## Assets

New animation frames must follow the zero-padded `frame-NN.png` naming and the `singingFrames` count in `app/page.js` must match the number of files.
